.. CG-EXPLANATION-START id=module-header

**What this does.** Opens the migration that adds the ``litho_build_generation`` table — one row per 3-D litho build, carrying its payload, settings, grid geometry and body-alias map — and links every built mesh to it. Names its revision id and the migration it follows.

**Why it is here.** The docstring records it is hand-written, not autogenerated: ``alembic revision --autogenerate`` proposed 66 operations, including dropping a dozen DOV-permkey indexes the import relies on, so only the two intended operations are kept and the unrelated drift is left for a deliberate separate migration.

.. CG-EXPLANATION-END id=module-header

.. CG-EXPLANATION-START id=function:upgrade

**What this does.** Creates the build-generation table (its columns record the build's settings, grid, payload, checksum and body aliases) with an index on model plus creation time, then adds a nullable ``generation_id`` column and foreign key to ``litho_body_solid``.

**Why it is here.** The inline comment records the link is nullable so meshes built before generations existed stay readable, and uses delete-sets-null rather than cascade because losing a mesh's provenance is recoverable but deleting the mesh with it is not.
