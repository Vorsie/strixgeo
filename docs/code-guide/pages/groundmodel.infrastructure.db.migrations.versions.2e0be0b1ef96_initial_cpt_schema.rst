**What this does.** Opens the very first migration in the chain — its ``Revises`` line is empty, meaning it has no down_revision and nothing runs before it. It creates the initial CPT storage.

**Why it is here.** Every schema history needs a root migration that a brand-new, empty database starts from; this is it, so it has no parent in the chain.

.. CG-EXPLANATION-START id=function:upgrade

**What this does.** Creates the ``cpt`` table (header fields, location coordinates, a PostGIS point geometry, and summary columns) with a spatial index on its location, and the ``cpt_series`` table holding the raw depth-series arrays (depths, cone resistance, sleeve friction, pore pressure, friction ratio) linked to the CPT with delete-cascade.

**Why it is here.** This is the storage behind the platform's first job — import a CPT and store it. The comment notes the columns were auto-generated by Alembic from the ORM models; the depth-series are stored as PostgreSQL arrays (one row per CPT), the recommended hybrid storage in CLAUDE.md "Depth Series Storage", and the spatial index (a GiST index) is what makes map and area queries fast.

.. CG-EXPLANATION-END id=function:upgrade
