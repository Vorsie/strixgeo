.. CG-EXPLANATION-START id=module-header

**What this does.** Header for the geotech axis's auto-correlate and accept verbs — the geotech counterpart of the litho correlation caret. Auto-correlate PROPOSES ties without touching existing ones; accept promotes the proposals the engineer keeps. Both take a scope: a section id runs on that section, null is the explicit all-sections escape.

**Why it is here.** Until these existed, the automatic packing ties could only be regenerated by 'Subdivide all bodies', which deletes the whole geotech model first — so getting the machine's ties back cost every hand-drawn correlation. Section scope is the owner's 2026-08-15 ruling ('this is model wide and not per section, i don't like that'). Lives outside the toolbar (debt #201).

**What this does.** What the verbs need: the project id, the active geotech model, the toast and mark-dirty actions, and the several refresh signals (correlation edges, body recompute, geotech layers, tie status).

**Why it is here.** The tie-status refresh fires after both verbs — one creates proposals, the other consumes them, and step 4's gate reads that number, so a stale count is the difference between a pressable button and a locked one.

**What this does.** Turns a scope (a section id, or null for the whole model) into a phrase — 'this section' or 'all sections' — for a toast.

**Why it is here.** Every toast names the scope (owner 2026-08-15): with two presses one menu apart, a count with no scope tells the engineer nothing about what moved.

``function useGeotechCorrelationVerbs``
---------------------------------------

.. CG-BLOCK id=function:useGeotechCorrelationVerbs lines=104-288

.. literalinclude:: ../../../desktop/src/renderer/src/shell/stages/sections/useGeotechCorrelationVerbs.ts
   :language: typescript
   :lines: 104-288

.. CG-EXPLANATION-START id=function:useGeotechCorrelationVerbs

**What this does.** Auto-correlate posts the proposal request scoped to the section, marks dirty and schedules the recompute when born-accepted restatements landed, refreshes the edge list and tie status, and toasts a scope-named result distinguishing restatements that band immediately from the machine's new pending density claims. Accept posts the approval, and when any tie was accepted refreshes the geotech layers, marks the borehole division stale and schedules the recompute, then toasts a scope-named count.

**Why it is here.** Auto-correlate is safe to press mid-session because it only inserts unapproved ties and leaves existing correlations alone; accept is the point at which the resolver folds them into bodies, which is why accepting a tie moves the body-id stamps and stales the borehole division. Litho-backed restatements arrive accepted (they band at once); the machine's new packing-density claims arrive pending for step 3's review (owner refinement 2026-08-06).
