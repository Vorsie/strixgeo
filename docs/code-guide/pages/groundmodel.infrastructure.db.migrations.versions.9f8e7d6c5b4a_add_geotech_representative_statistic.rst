.. CG-EXPLANATION-START id=module-header

**What this does.** Opens the migration that adds a pair of columns to ``geological_model``: ``representative_statistic`` (which averaging the NAD classifier reads — median, arithmetic, harmonic or geometric) and ``classified_with_statistic`` (which one the last full subdivide actually used). Names its revision id and the migration it follows.

**Why it is here.** The docstring records owner rulings 7 and 8 on the geotech hand-edit surface (debt #227): the representative qc statistic is selectable per geotech model, and changing it must mark the model's bands stale rather than silently re-deriving 500+ bands. Staleness is DERIVED, never stored — a build stamps the second column and a mismatch means stale — so it self-clears on rebuild or on flipping the choice back, with no clear-endpoint to get wrong. It is hand-written, not autogenerated, for the reason recorded in migration 2244cb54aa1c.

.. CG-EXPLANATION-START id=function:upgrade

**What this does.** Adds the ``representative_statistic`` column (defaulting to median) and the nullable ``classified_with_statistic`` column, adds check constraints restricting both to the four allowed tokens, and backfills the stamp to 'median' for geotech models that already carry accepted bands.

**Why it is here.** The docstring records median is the only statistic the classifier has ever used, so backfilling existing bands to 'median' means no spurious stale flag appears on upgrade; models never subdivided stay empty because nothing was classified and so nothing can be stale.
