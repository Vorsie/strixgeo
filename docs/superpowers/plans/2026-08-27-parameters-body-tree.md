# Parameters Body Tree Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist each geotech band's parent litho band as a DB foreign key, then rebuild the Parameters pane as the owner-ruled four-level tree (litho unit ▸ litho body ▸ NAD class ▸ geotech body) with one authority for what every node pools and shows.

**Architecture:** Two sequential slices. Slice A (backend): additive `litho_layer.parent_litho_layer_id` FK stamped at every geotech-band write, backfilled by the midpoint rule, exposed on the API response, proven by a .strix round-trip integration test. Slice B (frontend): a five-kind `ParameterUnitScope` union, a pure `parameterBodyTree.ts` module that owns both the tree and `bandsForScope`, the tree pane, the jump fallback ladder, and the cutout's body-set filter. Spec: `docs/superpowers/specs/2026-08-27-parameters-body-tree-design.md` — read it first; its rulings are verbatim owner contracts.

**Tech Stack:** SQLAlchemy + Alembic (hand-written migrations only — autogenerate is forbidden here, see any recent migration's docstring), FastAPI/Pydantic, React + TypeScript, Vitest, pytest.

**House rules that bind every task:** red-first pins phrased in the ruling's words; one file per commit, Conventional Commits, the repo's commit trailer; `uv run ruff format` + `ruff check --fix` are PostToolUse-hooked; integration tests ONLY via `.\scripts\run-integration-tests.ps1`; never edit while a commit batch's hooks run.

```python
"""Add litho_layer.parent_litho_layer_id — the geotech band's covering litho band.

Owner spec note 2026-08-27 ("can't you just create a foreign key … in the
DB?"). Band-level, not body-level: litho recomputes re-mint litho BODY ids,
so a body→body FK would dangle on every recompute; the covering litho BAND
is stable and the litho body is derived live through it.

Nullable and additive — restores from every existing .strix (the bundle
serialises columns generically). NULL = no covering accepted litho band
(true orphan), the state the Parameters tree reports honestly.

The backfill stamps existing geotech bands by the midpoint rule: the
accepted litho band on the SAME investigation whose [top, base) interval
contains the geotech band's vertical midpoint. Litho contiguity triggers
guarantee at most one such band.

HAND-WRITTEN, NOT AUTOGENERATED — same reason as 2244cb54aa1c.

Revision ID: c9d0e1f2a3b4
Revises: b8c9d0e1f2a3
Create Date: 2026-08-27
"""

from __future__ import annotations

import sqlalchemy as sa
from alembic import op

revision = "c9d0e1f2a3b4"
down_revision = "b8c9d0e1f2a3"
branch_labels = None
depends_on = None


def upgrade() -> None:
    """Add the nullable self-FK and backfill it for geotech-model rows."""
    op.add_column(
        "litho_layer",
        sa.Column("parent_litho_layer_id", sa.Uuid(), nullable=True),
    )
    op.create_foreign_key(
        "fk_litho_layer_parent_litho_layer",
        "litho_layer",
        "litho_layer",
        ["parent_litho_layer_id"],
        ["id"],
        ondelete="SET NULL",
    )
    op.create_index(
        "idx_litho_layer_parent_litho_layer",
        "litho_layer",
        ["parent_litho_layer_id"],
    )
    # Backfill: geotech-model bands take the accepted litho band on the same
    # investigation that covers their midpoint. gm.kind='geotechnical' and
    # gm.parent_model_id name the litho model (NAME-09 rename).
    op.execute(
        """
        UPDATE litho_layer g
        SET parent_litho_layer_id = l.id
        FROM geological_model gm, litho_layer l
        WHERE g.model_id = gm.id
          AND gm.kind = 'geotechnical'
          AND l.model_id = gm.parent_model_id
          AND l.status = 'accepted'
          AND (
                (g.cpt_id IS NOT NULL AND l.cpt_id = g.cpt_id)
             OR (g.borehole_id IS NOT NULL AND l.borehole_id = g.borehole_id)
          )
          AND (g.depth_top_m + g.depth_base_m) / 2.0 >= l.depth_top_m
          AND (g.depth_top_m + g.depth_base_m) / 2.0 <  l.depth_base_m
        """
    )


def downgrade() -> None:
    """Drop the parent-band FK, index and column."""
    op.drop_index("idx_litho_layer_parent_litho_layer", table_name="litho_layer")
    op.drop_constraint(
        "fk_litho_layer_parent_litho_layer", "litho_layer", type_="foreignkey"
    )
    op.drop_column("litho_layer", "parent_litho_layer_id")
```
