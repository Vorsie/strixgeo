# Watertight Loft Body Builder — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the per-body TIN internals of `build_body_solids` with a loft pipeline that interpolates the validated 2D section partitions into a mathematically watertight 3D body model (no holes, no overlaps, no disk markers), persisted in the DB and the `.strix` bundle.

**Architecture:** Pure Python domain services: a faithful port of `computeSectionFill` (golden-parity-pinned to the TS original) supplies per-section partitions; a loft field blends the two nearest sections per map-plane node (matched by `body_id`, pinching one-sided bodies at the equidistance midline); a wedge mesher emits per-triangle prisms that share faces by construction. `RecomputeLithoSolids` keeps its full external contract (endpoint, response, `litho_body_solid` rows, staleness).

**Tech Stack:** Python 3.11, scipy ≥ 1.13 (`scipy.spatial.Delaunay` — already used by `compute_tin`), NumPy, pytest; one Vitest fixture-generator on the TS side.

**Spec:** `docs/superpowers/specs/2026-06-12-watertight-loft-body-builder-design.md`.

**Base / branch:** branch `feat-litho-3d-watertight-loft` off `develop`. Do NOT push (`feedback_git_workflow`). Unit tests: `uv run pytest tests/unit -q`. Integration: `.\scripts\run-integration-tests.ps1` (NEVER bare pytest against the dev DB). Desktop gates only where the golden generator is touched: `npx tsc --noEmit -p tsconfig.web.json` + `npx vitest run` from `desktop/`.

**Owning layer (first gate):** Python domain (`src/groundmodel/domain/services/`) + application wiring. The 2D renderer, 3D viewer, fence, and API schemas are NOT touched (except the bundle repository and two e2e specs).
