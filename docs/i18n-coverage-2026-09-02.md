# NL i18n coverage — renderer string audit (2026-09-02)

This note records the one-shot coverage pass that routed every stray user-facing
English string in the renderer through the message catalogue so the app in Dutch
mode shows no untranslated interface chrome. It pairs with the repeatable finder
at `desktop/scripts/find_untranslated.mjs`.

## The finder

`node desktop/scripts/find_untranslated.mjs` parses every renderer `*.ts(x)`
with the TypeScript compiler and reports display-position string literals that do
not go through `t()` / `useT()` / `translate()`. It exits non-zero on any
finding. It is a MANUAL gate — deliberately not wired into a hook or CI in this
slice. `--json` emits machine-readable output; `--only <substr>…` restricts the
report to matching paths.

### What it flags (display positions only)
1. JSX text nodes carrying real words — `<span>Save</span>`.
2. A curated allow-list of user-facing JSX string attributes: `title`,
   `placeholder`, `alt`, `label`, `aria-label`, `aria-description`,
   `aria-roledescription`, `aria-valuetext`, `aria-placeholder`.
3. The message argument of a `toast(type, message)` call.
4. Display-position string / template literals inside the above — a conditional's
   two results, a logical / nullish right-hand side, a `+` concatenation, a
   template's literal chunks. It never descends into a condition, a comparison,
   or an arbitrary function call's arguments, so a `status === 'done'` operand is
   never mistaken for copy.

### Exclusion list (documented in the script header)
- **Directories**: `components/onboarding/`, `components/licensing/`,
  `components/updater/` (prototypes with their own `launch` catalogue, out of
  this slice), and `i18n/` itself (the catalogues ARE the translations).
- **Files**: every `*.test.tsx` / `*.test.ts` / `*.spec.*` / `*.d.ts`, plus any
  `__mocks__` / `__tests__` / `e2e` subtree.
- **Attributes not in the allow-list** — `className`, `id`, `key`, `role`,
  `type`, `name`, `href`, `src`, `data-testid`, SVG geometry, and the
  `aria-*by` id-reference attributes are never inspected.
- **Sinks other than `toast`** — `log.*` and `console.*` calls are never
  descended into; log output is not a display position.
- **Translator calls** — a `t()` / `translate()` / `useT()` argument is never in
  a display position and its call is never descended into.
- **Domain-canon tokens** — soil names, NAD packing-class names/codes, lithology
  labels, lab-test labels, DOV codelist tokens. These render Dutch by SELECTING a
  source token (backend `NAD_CLASSES`, `soilColors.ts`, `lithoConstants`,
  `labTestLabels.ts`), not through the catalogue, per docs/ux.md. They reach the
  DOM through lookup calls, not literals; the few that surface as bare literals
  carry an inline `// i18n-exempt:` marker.
- **Unit / symbol tokens** — `MPa`, `kN/m³`, `m TAW`, `%`, `°`, numeric-only, and
  the like; identical across locales, skipped by the `SYMBOL_ONLY` heuristic.
- **Inline exemption** — any literal on a line (or the line above) carrying an
  `i18n-exempt` marker with a reason. Used for developer-only chrome and the few
  symbol/format literals the heuristic misses.

The `sheet` PDF-export catalogue named in the slice brief is not present on this
branch (it is in flight on a separate branch); nothing to exclude for it here.

## Deliberately left English

**Domain-canon / symbol literals** carrying an inline `// i18n-exempt:` marker
(render Dutch by selecting a source token, not via the catalogue — per
docs/ux.md and `i18n/locales/en/index.ts`): CPT channel + unit symbols
(`qc/Qt/fs/Rf/u`, `MPa/kPa/%`, `mTAW`, `SBT`/`SBTn`, `Ic`, `x/y`, `cu/OCR/Vs/φ′/c′/E50`)
in `CptChart`, `CptSbtDepthPanels`, `UnitIdentificationPanels`, `PerTestTab`,
`SectionPanel`; `EPSG:` CRS-registry prefix in `ElevationEditor`,
`ProjectMetadataDialog`; the `DOV` brand name in `BoreholeLog`, `CptChart`;
Belgian formation proper nouns ("Boom Klei"/"Diest Zand") and the "lid" (member)
rank token in `FormationDialog`; `&nbsp;` in `SectionsInspector`.

**Finder blind spots — user-facing English the finder cannot see** (it inspects
display positions, not module-level data structures or out-of-scope helpers).
Recorded as follow-ups, NOT lifted this pass:

- **`CheatsheetDialog` `GROUPS`** — the whole keyboard/gesture reference (~80+
  trigger/action strings in a module-level const). Only the dialog chrome
  (title, search, empty state) was wired. The catalogue already pre-seeds
  `cheatsheet.*` section headings, signalling a planned full pass. Recommend a
  dedicated cheatsheet-i18n slice (dense gesture vocabulary, review-heavy) over a
  half-translated state.
- **`utils/recoveryAge.ts`** — the `{age}` phrase ("5 minutes ago", "just now")
  interpolated into the recovery dialogs stays English (out of the file scope).
- **`useLithoSuggestions` `undoDescription` (5 sites)** — undo-history labels fed
  to `pushUndo`; a cross-cutting undo-i18n concern (also `utils/lostTieMessage`,
  `utils/divideBoreholesToastMessage`) beyond this pass's file scope.
- **Grain-fraction chart labels** (Clay/Silt/Sand/Gravel/Cobbles in `LabTestPanel`)
  left English as domain-canon — but this conflicts with the pre-existing
  `lab.cobbles`='Keien' / `lab.atterberg` catalogue entries. Owner decision:
  source these from `utils/soilColors.ts`, or catalogue the grain fractions
  (silt→"Silt" vs "Leem" needs a ruling).
